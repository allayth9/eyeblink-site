## المرحلة 1: Architecture & Code Audit ✓ (12 نوفمبر)

- قراءة فقط، بلا أي تعديل. التقرير الكامل بالمحادثة، وأهم النتائج:
  - `admin/admin.js`: ملف واحد 392KB / 2289 سطر، و72 متغيّر حالة مشترك.
  - التنقل بالذاكرة (`TAB`): لا رابط لكل قسم، وزر الرجوع بيطلّع من اللوحة.
  - 4 طرق مختلفة لعرض التفاصيل: صف بيتوسّع، وشريط جانبي، ونافذة منبثقة، وصفحة ملف.
  - كلمة السر محفوظة بـ sessionStorage وبتنبعت كـ Bearer مع كل طلب.
  - العميل بمصدرين (KV للحساب، D1 لجدول العملاء)، والفوترة بمصدرين (D1 للفواتير، KV لدفعات الطلبات).
  - النسخ الاحتياطي بيشمل محتوى الموقع بس.
  - أسماء الحالات وألوانها معرّفة بـ 4 أماكن.
- إعادة فحص حقن الكود بكل الأقسام والتبويبات الفرعية: ولا شي اشتغل.

| بحاجة لقرارك | نفس التنبيهات، وكل سطر معه زرّه (افتح، رد، راجع…)، والعاجل والانتباه مميّزين | `alerts()` |

| الأيام الجاية | مربعات تاريخ | نفسها |

## المرحلة 6: أقسام الشغل (فرع `admin-polish`)

**تعديلين على الخلفية والنص (طلب ليث):** الشهاب صار جزء من الخط نفسه (نفس التدرّج، أسطع، راس وذيل بيخفت)، مش خط أبيض منفصل. والنص الهادئ صار أوضح بالوضعين (`--dim`)، والعناوين اللي فوق الخلفية مباشرة صار وراها ظل ناعم حتى ما يقطعها خط. هاد قاعدة لكل الصفحات.

**الطلبات (أول قسم):**

| شو | التفاصيل |
|---|---|
| قائمة + لوحة | كل طلب صار سطر مختصر (الاسم، والرمز، والباقة، والمرحلة، والقيمة، والرسائل الجديدة، والمتابعة). الطلب المختار بيفتح باللوحة جنب القائمة بكل محتواه وأزراره متل ما كان |
| الرابط | `/admin/orders/<رمز>`. الرجوع والتحديث والرابط المباشر شغّالين |
| لوحة المفاتيح | ↑ ↓ بيتنقّلوا بين الطلبات (إلا وقت الكتابة) |
| الموبايل | القائمة لحالها، والطلب بيفتح بصفحة كاملة مع «كل الطلبات» للرجوع، والإحصاءات والفلاتر بتختفي وقتها |
| الدخول للطلب من برّا | من «اليوم»، ومن الفوترة، ومن ملف العميل: كلهم بيفتحوا الطلب باللوحة مباشرة |
| الخط بالأزرار (طلب ليث) | خط Hayyakum فيه وزنين بس (عادي ومتوسط). الأزرار الأساسية كانت تطلب 600، فالمتصفح كان «يخترع» عريض بتسميك الحروف. الحل من الجذر: `font-synthesis:none` على كل اللوحة (ممنوع العريض المزيّف)، والأزرار والنص العريض صاروا بالوزن المتوسط الحقيقي (500). العناوين بـ EYEN Ammon والأرقام بـ Oswald ما تأثروا |

**العملاء (القسم التاني):** كان أصلاً «قائمة + صفحة كاملة بتبويبات»، فالشغل ترتيب وتهدئة:

| شو | التفاصيل |
|---|---|
| صورة العميل | بتدرّج الهوية للكل بدل لون عشوائي لكل عميل |
| سطر القائمة | الأرقام اللي إلها قيمة بس، كحبّات صغيرة («1 مشروع · 3 مهام مفتوحة»)، بدل «0 0 0» |
| أزرار ملف العميل | «تعديل البيانات» + الفعل الأساسي (ترقية/تجهيز حساب) ظاهرين، والباقي (بيانات دخول جديدة، إلغاء مساحة العمل، أرشفة، حذف الحساب) بقائمة «⋯» بتتسكّر لما تكبس برّاها |
| بطاقات الأرقام الست | زجاج موحّد، والمستحق بلون «بانتظار» والمدفوع بلون «تم» بس |
| التبويب المختار | بتدرّج الهوية |

## المرحلة 6 · المشاريع والمهام (12 نوفمبر)
- تبويبات: المهام · المشاريع · إعدادات نموذج المهمة، بعناوين /admin/tasks و/projects و/settings.
- المهام قائمة صفوف + لوحة جنبية متل الطلبات (wtaskRow)، و«بانتظار قرارك» بأول القائمة. الفلاتر بنفس سطر التبويبات.
- زر «مهامه» بالمشروع بيرجع لتبويب المهام مفلترة. انحذف فتح البطاقة بمكانها (toggle).
- موبايل: القائمة، وبعدين المهمة لحالها مع «‹ كل المهام».
- ألوان دلالية «بين الاثنين»: بطاقات أرقام معبّاة بتدرّج معناها (kc() بـ 03-shell، والصفر زجاج)، صفوف هادية بخط حالة (tf-*)، والتاريخ لونه حسب قربه، و«متأخرة» شارة معبّاة، وحلقة الحصة الشهرية للمشاريع (wring). المجموعات نفسها للأرقام والصفوف (TFAM).
